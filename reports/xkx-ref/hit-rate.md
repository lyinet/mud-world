> `feature/skill.c` 的 `query_skill()` 非 raw 时返回 `skills[skill]/2 + skills[skill_map]`，所以 MID 显示 40 级，战斗有效等级是 **20**。

## 3. 计数口径

- 出手：动作行以 `！` 结尾且满足“你…<对手>的…”或“<对手>…你的…”；“企图/准备发动攻势/缓缓移动脚步/注视/喝道”等非攻击行剔除。
- 结果：动作行之后第一条非状态行；含 `挡/格/架/招架/封/拨` → 招架；含 `闪/躲/避/侧身/滑开/偏了几寸` → 闪避；以“结果”开头 → 命中；其余记 `other`。
- 伤害：`combatd` 的 `damage_msg` 文案档位取中值（例如“瘀伤”记 10–19、记 14.5），只作量级估计。
- 回合：一次出手 = 一次判定；每场景累计双方各 ≥50 次。老虎场景玩家 0 次出手，按对方出手 ≥50 计。

## 6. 与 combatd.lpc 参数相关的线索

### 6.1 可观察（原始文本/面板直接给出）

- 双方出手数、命中/被闪/被招架数：来自动作行与结果行。
- 我方 `hp`/verbose 气值变化：来自 `【气血】` 与 `┃精：…气：…┃`。
- 我方 `score`/`skills`/携带/天赋：来自命令输出与存档字段。
- 对手 `look` 描述（名称、性别、体型、武器有无等）。
- **老虎场景玩家 0 次普通出手**：日志里只有“你慢慢地移动着脚步，伺机出手。”一次，之后玩家侧不再出现任何动作行——这是可观察事实。

### 6.2 只能推断（源码事实，非本次实测可观察）

- `skill_power()`：`level = query_skill(skill) + apply/attack|defense`；level=0 时返回 `combat_exp/2`；`power=(level/6)*level*level`；攻击力 `(power+exp)/80*(str+str_temp)`，防御力同式用 dex；str/dex 夹在 10..200。
- `query_skill()` 非 raw：`skills[skill]/2 + skills[skill_map]` → 显示 40 级 = 有效 20 级。
- 命中判定顺序：先闪避 `random(ap+dp) < dp`，未闪再招架 `random(ap+pp) < pp`，都不过才命中。
- **老虎的 cps=0 是 0 出手的直接原因**：`combatd.c` fight() 里 `random(victim->query_cps()*3) > me->query_cor()`；`adm/daemons/race/beast.c` 不设 cps/cor，老虎 `query_cps()=0` → `random(0)=0`，玩家胆识 24 也永远进 guard 分支，首条 guard 文案后 `guarding=1` 静默。
- 老虎 dex/str/con 未在 `laohu.c` 设置，由 `beast.c` 每个 clone 掷 `random(40)+5`——所以老虎的 dex 不是常数，只能从战斗数字反推。
- `skill_power` 的 level 上限 800：老虎 `apply/defense=30000` 会被截到 800，这是“老虎几乎必中/玩家几乎打不中”的数值来源。

### 6.3 不可观察

- 对手的 exp、技能等级、apply/attack|defense、dex/str/con 的**运行时真实值**（源码可读，但面板看不到；老虎 dex 还每只随机）。
- `ap/dp/pp` 中间量本身（只能由公式反推）。
- 我方 `耐力/胆识/福缘` 的 score 显示值（面板为 `???`）。

## 7. 局限与备注

- 伤害是文案档位估计，不是精确值；命中率与闪避/招架计数不受影响。
- 每条命结束就重启实例（死亡后位置/血量无法在同一次会话里干净复位），所以样本由多条命拼接；每条命的对手都是新 clone。
- 老虎场景按对方出手计回合；我方 0 出手是原版设计使然，不是采集失败。
- MID 的 `startroom` 直接指向目标房间（存档字段），省掉 44 步/夜间出口不可见等与命中率无关的环境噪声；`wudang.offerring=100` 仅用于过遇真宫山门（非战斗字段）。两者都写在存档里，LPC 未改。
