# 目标生命周期审计（A3：M 臂 vs R 臂）

**结论：切换摊薄假设不成立（至少不成立为“切换频率/已积累进度被摊薄”）；M 臂切换更少、丢弃更少、完成更多，K1 仍低 4.40pp。真实原因是模型对初始内容目标的单向覆盖与目标类型组合偏移：模型自选目标通过率高，但被替换的 planner 初始目标大量停在 0，K1 差值正好落在初始目标上。**

- M 臂：`runs/a3-model2-10d-31npc`（K1 41/91 = 45.05%，events 3697，hash `c4fc017c…`）
- R 臂：`runs/a3-rule-10d-31npc-a3`（K1 45/91 = 49.45%，events 3307，hash `9bb08af8…`）
- 审计脚本：`tools/goal_lifecycle_audit.py`，只读 `events.jsonl` / `summary.json`，零模型调用、零 API 成本。
- 事件重建与 summary 的 K1 行对照：91 个内容目标 **0 个进度/状态不一致**，可认为生命周期重建可靠。

## 1. 方法与口径

### 1.1 数据与重建

按 `seq` 顺序重放事件里的 `goal_create` / `set_field(goal_id)` / `goal_progress` / `goal_abandon`：

- `goal_create`：目标创建，并把该 NPC 的当前目标切到新目标；
- `set_field(goal_id)`：把当前目标切到已有目标（模型可重复选择同一目标）；
- `goal_progress`：累计归一化进度（`0..1`），到 `1.0` 记完成并清空当前目标；
- `goal_abandon`：记放弃；同一 `system_goal` 事件通常随后创建/切换新目标。

### 1.2 指标定义

| 指标 | 定义 |
|---|---|
| 生命周期 | `created_tick` → `completed_tick` / `abandoned_tick` / 最后一次活跃 tick（或 run 结束 tick 1439） |
| 存活 tick | 该目标作为 NPC 当前目标的 tick 并集；激活 tick 计入，被切换 tick 不计，完成 tick 计入 |
| 切换 | 当前目标 A 被另一个目标 B 激活替换；完成不算切换 |
| 切换来源 | `model_over_planner`（模型覆盖规则）、`planner_over_model`（规则/紧急覆盖模型）、`model_internal`（模型内部换题）、`planner_internal`（规则内部换题） |
| 往返切换 | 被切走的目标在之后又被重新激活；其余为单向切换 |
| 丢弃率 | 至少离开过一次（切换/放弃）且最终未完成的目标 / 全部已创建目标 |
| 沉积进度 | 未完成且离开过的目标的期末归一化进度之和（单位：目标进度当量，1.0 = 一个目标完成） |
| 丢失进度占比 | 沉积进度 / 两臂各自全部目标期末进度之和 |

### 1.3 丢失进度的计算与假设

主指标是**沉积进度**：目标被切走或放弃时已经积累、但到 run 结束仍未完成的进度。它是事件可精确重建的“存量”，但**不是因果上的未来损失**。

辅助给出**反事实增量**：假设该目标最后一次离开后一直保持活跃，按它自身的“每活跃 tick 进度”外推到 run 结束，还能多积累多少。该数字依赖三个强假设：

1. 目标保持活跃时的边际进度率不变；
2. 没有其他目标争抢同一 NPC 的 tick；
3. 目标在 10 天窗口内不会因为外部条件变化而变难。

因此反事实只作情景参考，不用于判定假设成立与否。

## 6. 假设与局限

1. **进度是归一化值**：`goal_progress` 的 delta 已按目标阈值归一化，`1.0` 表示完成；K1 的“progressed”阈值是 `>0.1`，不是完成。
2. **活跃 tick 是半开区间**：切换 tick 不计入旧目标，完成 tick 计入；同一 tick 内多次切换只按事件顺序处理，可能低估极短的重叠。
3. **生命周期按事件重建**：事件不含每个 tick 的完整状态快照，因此“最后一次活跃 tick”是重建值；已用 K1 行做 0 不一致校验。
4. **K1 分母与生命周期分母不同**：K1 的 91 个内容目标包含未创建目标，也排除由动作创建的 `found_*` 特殊目标；生命周期审计统计所有实际创建目标（M 90 / R 89），所以通过率分母不同，不能直接把 60.29% 与 49.45% 混用。
5. **沉积进度不等于因果损失**：它只说明“这些进度到期末仍未完成”，不证明“如果不切换就一定能完成”；反事实增量是情景估算，假设边际进度率不变且无竞争。
6. **10 天窗口截断**：长期目标在窗口结束时天然更容易显示为未完成；两臂同窗口可比，但不能外推到更长周期。
7. **切换来源依赖 `goal_source` 标记**：`model` / `content` / `urgent` 由调度层写入；未标记的激活归为 `system`（本次两臂为 0）。

## 7. 结论与第二段判断

**一句话：切换摊薄假设不成立。** M 臂切换更少（45 vs 88）、平均存活只短 2.9%、沉积进度占比更低（8.77% vs 32.61%）、完成率更高（32.22% vs 22.47%），但 K1 仍低 4.40pp。真实原因是：

1. 模型对规则初始目标做了 **25 次单向覆盖**，被覆盖目标只有 9 次返回，导致初始目标通过 13/31（R 16/31）、16 个停在 0；
2. 模型把目标组合偏向 `build_relation`（+4），同时少做 `build_shop`（−3）、`earn_money`（−3）、`advance_skill`（−2）；
3. 这两项合起来正好对应 K1 的 −4：不是“切换频率高导致每个目标都摊薄”，而是“**高产出目标替换了规则初始目标的连续性，且类型组合变窄**”。

**第二段开工条件：不具备。** 第一段没有证实“承诺窗口/滞回”要解决的切换摊薄问题；如果此时实现承诺窗口，最可能的效果是把模型锁在初始目标上，未必能补回类型组合缺口。建议第二段先不做，或改为针对“初始目标单向覆盖 + 类型组合”另立假设。
