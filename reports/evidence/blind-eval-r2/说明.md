# R2 盲评包说明：模型 vs 正常短模板

## 用途

本包只回答一个问题：**在“模板侧是正常短回应”的前提下，模型回复是否仍优于模板？**

旧的 `reports/a2-dialogue-eval/blind_pairs.jsonl` 模板侧统一是“约 150 字第三人称人格档案 + 一条固定台词”，30 条里 27 条与玩家输入无关。旧包 100% 的模型胜率主要检测到的是**模板实现失效**，不能外推到“模型 vs 正常模板”。因此重建本包，把模板侧换成 20–60 字、第一人称、按意图回应的短模板，其余条件保持不变。

## 本轮修复：意图分化

上一版 R2 模板已能回应具体话题，但仍被发现有“只换话题名词”的问题：问肉价与问赊账的后半句完全相同。本轮把模板按意图拆成独立骨架，每个类别有自己的语义内容：

| 类别 | 骨架语义 |
|---|---|
| 问价/谈生意 `price` | 行情、看货定价、让零头、验秤 |
| 赊账/借钱 `credit` | 赊期、先付一半、到期催讨、拒绝再赊 |
| 问路 `directions` | 东街/石桥/红灯笼、蓝布帘、老槐树等地标 |
| 打听消息 `gossip` | 人物两说评价、传言真假、财不露白提醒 |
| 闲聊 `chitchat` | 磨刀出摊、案板裂纹、酒、手艺、夜里走路等个人细节 |
| 求助 `help` | 先讲条件、能应与不能应、邀请喝酒另用骨架 |
| 拒绝 `rejection` | 不强卖、留余地、记脸不记仇 |

台词（`>` 引用）只挂在“回避”骨架上，跨类别不再复用同一句尾口号。

## 本轮修复（第三版）：意图 × 诉求对象二维分流

上一版虽按意图分化，但所有生意类问题仍共用 `price` 骨架：问绣品、猪下水、瘦肉切法、盘铺子本钱，都会答成“肉价、让零头”。本轮加入**诉求对象**识别，骨架改为“意图类别 + 对象类型”二维匹配：

- 商品：肉价 / 猪下水 / 瘦肉切法 / 非肉品类（绣品等）各用独立骨架；
- 钱务：赊账与盘铺子的本钱分开；
- 人物：具体人名（金掌柜、孟九娘等）走人物评价或关系骨架；泛称“读书人”走人物类型骨架，不再当成人名；
- 地点：问路走地标骨架；
- 消息：传言、人物评价、北边对生意的影响分开；
- 杂务：求助、学手艺、邀请喝酒、拒绝各用不同骨架。

评审点名的 7 条错配与新骨架：

| id | 玩家原话 | 旧骨架 | 新骨架 |
|---|---|---|---|
| 5 | 柳三娘做的绣品，你可买过？ | `price` | `price.other` |
| 23 | 今日可有新鲜的猪下水？ | `price` | `price.offal` |
| 29 | 我想买半斤瘦肉，怎么切最好？ | `price` | `price.cut` |
| 20 | 我想盘个铺子，要多少本钱？ | `price` | `price.capital` |
| 27 | 你觉得读书人靠得住吗？ | `gossip.person` | `gossip.type` |
| 28 | 最近夜里可有怪声？ | `chitchat.safety` | `chitchat.sound` |
| 15 | 你家里还有些什么人？ | `chitchat.daily` | `chitchat.family` |

同对象连续两轮仍由 `turn % 2` 的 a/b 变体轮换；不同对象不复用同一骨架 id。

## 样本来源

- 玩家输入：`runs/a2-dialogue-30/eval_raw.jsonl` 中的 `message` 字段，共 30 条，原样复用。
- 模型回复：同一文件的 `model_reply` 字段，共 30 条，原样复用；来自 2026-11-04 已落盘的 dialogue 槽真实调用记录（目标 NPC `duan_wudou`）。
- 模板回复：由当前 `src/wsim/agent/dialogue.py::compose_talk` 对同一 `message` 与同一 `tick` 重新生成（`turn=0`）。

## 为什么不重跑模型

1. 模型回复已经落盘，重跑不会产生新的评测信息，只会引入 API 成本。
2. 同一输入重跑模型会因采样温度产生文本漂移，导致新旧两包不可比。
3. 本次修复只改模板侧；重跑模型会同时改变两个变量，破坏“只替换模板”的对照设计。

## 盲评方法

1. 只读 `pairs.jsonl` 的 `id/prompt/A/B`，按角色一致性、上下文相关、自然度、信息量四项各打 1–5 分，并独立判 A/B/平手。
2. 30 对全部评完后，再读 `answer_key.jsonl` 解盲。
3. `answer_key.jsonl` 中 `model` 字段表示模型回复所在位置（`A` 或 `B`）。
4. 位置平衡：模型作为 A 出现 15 次、作为 B 出现 15 次。

## 检查结果

| 项目 | 结果 |
|---|---|
| 样本数 | 30 |
| 模板长度最小值 / 最大值 / 平均 | 28 / 41 / 35.0 字 |
| 落在 20–60 字 | 30 / 30 |
| Markdown 标记命中 | 0 |
| 第三人称叙述命中（`他` / `她`） | 0 |
| 缺第一人称 `我` | 0 |
| 跨意图最大字符相似度 | 0.3429（chitchat vs help，阈值 0.60） |
| 同一骨架最大复用次数 | 3 / 30（上限 3） |
| 包内出现的意图类别 | price / credit / directions / gossip / chitchat / help |
| `pairs.jsonl` 字段 | `id, prompt, A, B` |
| `answer_key.jsonl` 字段 | `id, model` |
| 来源标签是否只在 answer_key | 是 |

长度分布：20–29 字 2 条，30–39 字 25 条，40–49 字 3 条，50–60 字 0 条。

骨架分布（30 条）：`gossip.event.a` 3 次；`chitchat.craft.a`、`gossip.person.reputation.a`、`gossip.person.relation.a`、`price.meat.a` 各 2 次；其余 16 个骨架各 1 次。

回归测试 `tests/test_dialogue_intents.py` 另用 8 个类别 × 5 条输入检查（含 rejection / deflection），跨类别最大相似度 0.3636，且各类骨架 id 互不相交。`tests/test_dialogue_routing.py` 锁定本轮 7 条错配原文、泛称人物分流，以及 R2 样本同一骨架最多 3 次；R2 的 30 条输入本身没有拒绝/回避样本，这两类由前一个测试覆盖。

检查逻辑见 `build_r2.py` 中的 `MARKDOWN_RE` / `THIRD_PERSON_RE` / `FIRST_PERSON` 与 `SequenceMatcher`，结果写入 `checks.json`（含 `similarity_matrix`、`skeleton_counts`、`routing`）。

## 文件清单

- `pairs.jsonl`：30 对匿名 A/B，无来源标签。
- `answer_key.jsonl`：30 条 `id → model 所在位置` 映射，评分前不要打开。
- `checks.json`：长度、格式、字段、位置平衡、意图骨架与相似度矩阵、哈希指纹。
- `build_r2.py`：可复现生成脚本，不调用任何模型接口。

## 适用边界

- 模型侧保留旧包原始文本，其中仍可能包含 Markdown 动作标记或第三人称叙述（这是旧模型真实表现，本包不改写被评测对象）。
- 模板侧是规则模板，能回应具体话题并保持人物口吻，但不承诺给出事实性世界信息；它的作用是提供“正常短模板”基线，而不是替代模型。
- 旧包 `reports/a2-dialogue-eval/` 保持原样，未被覆盖。
