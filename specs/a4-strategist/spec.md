# Spec · A4 长周期战略层（只做设计，不实现）

- 状态：**设计稿**；本任务不改 `src/wsim/**`，不做 git 写操作以外的实现。
- 目标：把 LLM 从“每 tick 选目标的选择器”改成“每 NPC 每 N 游戏日一次的长期战略层”，由规则 planner 负责 tick 级动作。
- 结论一句话：**有条件值得做**——不值得作为提升 K1 的主线，只值得作为一次有硬预算、有预注册失败条件的受控实验；若达不到计划类指标门槛，转内容扩充或对话/叙事层。

## 1. 判断：为什么“有条件值得做”

**不成立的部分**：A3 三次尝试加冻结快照都表明，模型在“每 tick 选目标/选动作”这一层对 K1 的增量约为零；继续加调用量或继续调 prompt 不成立。

**仍可检验的部分**：生命周期审计显示 M 臂切换并不比 R 多（105 vs 105），完成率更高（25.22% vs 20.51%），但 K1 仍打平；损失集中在“模型单向覆盖了有进度的规则初始目标”和“类型组合变窄”。这给出一个**不同的假设**：把模型降频为多日组合层、禁止它每 tick 推翻计划、让规则 planner 执行，可能提升“计划完成率/连续性”，而不是 K1。

**值不值得**：只有当它**替代**现有 decision 选择器（不是叠加）、10 天总成本 ≤$1.5、且计划类指标显著优于规则时，才值得继续。若需要 $3.0/10 天或只提升 K1 名义值，直接判不值得，转替代方向。

## 2. 调用频率与分工（问题 1）

### 2.1 频率

- 默认 **S0**：每个 NPC 每 **3 游戏日 1 次**，只在日界调用：day 0/3/6/9（10 天共 4 轮）；31 NPC → **124 次/10 天**；72 天 → 24 轮 × 31 = **744 次**。
- 周期内**不再调用**战略层；目标完成/放弃/紧急事件都不触发新模型调用，只在下一个日界重规划。
- 可选 **S1**（只作为成本上界对照，不作默认）：每 NPC 每游戏日 1 次，310 次/10 天、2232 次/72 天。
- 分层可选（后续优化，不进入首轮）：spotlight/active 1/3 天，background 1/6 天，silent 1/10 天。首轮用统一 1/3 天，避免把“层数变化”混进对照。

### 2.2 分工

| 层 | 负责 | 不负责 |
|---|---|---|
| 战略层（LLM，低频） | 定方向：3 日组合（1 主目标 + ≤2 次目标）、关系对象、现金/支出预算、风险偏好、理由 | 不输出任何具体动作、动词、参数、地点；不改 `RULE_VERBS`；不在周期内改计划 |
| 规则 planner（每 tick） | 定动作：生存/通勤/上工/吃饭/修炼/买卖/任务/社交动作，全部前置条件、定价、重规划 | 不擅自改战略方向；只有计划不可行时按规则降级并留痕 |
| GoalSelector | 把战略组合映射成内容目标优先级；执行承诺窗口与护栏 | 不每 tick 接受模型覆盖 |
| 紧急层（规则） | 受伤/被追债/破产抢占，暂停当前计划；紧急解除后恢复原计划 | 模型不得抢占紧急目标 |

一句话：**战略层定“这 3 天做哪几件事”，规则层定“今天这个 tick 做什么动作”。**

## 3. 战略产出物形态与消费约束（问题 2）

### 3.1 产出物：`StrategyPlan`（只含方向，不含动作）

```json
{
  "plan_id": "plan:<npc>:<created_tick>",
  "npc": "<npc_id>",
  "created_tick": 0,
  "expires_tick": 432,
  "horizon_days": 3,
  "primary_goal_id": "<content_goal_id 或 null>",
  "secondary_goal_ids": ["<goal_id>", "<goal_id>"],
  "relation_targets": ["<npc_id>", "<npc_id>"],
  "budget": {
    "cash_floor": 40,
    "max_discretionary_spend": 200,
    "max_goal_actions_per_day": 2
  },
  "preserve_goal_ids": ["<active_goal_id>"],
  "type_quota": ["build_shop", "earn_money", "advance_skill"],
  "confidence": 0.6,
  "rationale": "<=80 字，第一人称，可审计"
}
```

- 只允许 NPC 自己的内容目标或已存在目标；不得引用别人的目标、已完成/已放弃目标、不存在的地点/物品/人物。
- 不包含 `verb`、`args`、`target` 动作参数；不包含 `system_*`。
- 每份计划最多 3 个目标；`relation_targets` 只用于规则选择 `trade/talk` 的对象偏向，不直接生成动作。

### 3.2 消费方式

1. **只在日界读取一次**：`GoalSelector` 在 strategy 生效 tick 读取计划；周期内忽略任何新的模型输入。
2. **优先级**：`primary` → `secondary` → 内容包默认优先级；同一 NPC 同一时刻仍只有一个 active 目标。
3. **承诺窗口**：计划生效后至少保持 **3 游戏日（432 tick）**，或直到目标完成/放弃/紧急抢占；周期内模型不能改计划。
4. **紧急暂停与恢复**：紧急目标由规则抢占；计划不放弃，紧急解除后回到计划原主目标（若未过期）。
5. **不可行降级**：计划目标不可达/前置不满足时，规则按 secondary → 默认内容目标降级，写 `strategy_deviation`，不调用模型。
6. **journal 而非事件**：计划、校验结果、消费记录、偏差写 `runs/<id>/strategy.jsonl`；不写入 `events.jsonl`/`WorldState`，关闭开关时事件流与哈希不变。

### 3.3 防止“每 tick 被推翻”的护栏

- **G1 进度保护**：当前规则目标 `progress >= 0.1` 或预期完成概率 ≥0.55 时，计划必须把它放进 `primary`/`secondary`/`preserve_goal_ids`，否则整份计划判非法。
- **G2 紧急优先**：`choice.source == "urgent"` 时战略层不参与，urgent 仍由 `GoalSelector._urgent` 抢占。
- **G3 类型配额**：NPC 仍有未完成的 `build_shop/earn_money/advance_skill` 时，组合至少含 1 个核心类型；否则判非法（复用 A3 类型配额思路）。
- **G4 预算约束**：`cash_floor` 是硬下限；规则 planner 在会跌破下限时**延后**目标动作，不拒绝、不借债。
- **G5 单周期单计划**：同一 NPC 同一 `plan_id` 只能被消费一次；重复/过期计划直接忽略并留痕。
- **G6 回放**：strategy prompt/output 走现有 record/replay transport；回放必须产出同 `plan_id`、同消费结果、同 `event_hash`。

## 4. 可测指标（问题 3）

不再用 K1 作唯一判据。以下 5 个为主指标，K1 只作护栏。

### M1 计划完成率 PCR（Plan Completion Rate）

- 计算：`PCR = 在 expires_tick 前完成（progress>=1.0 或 status=completed）的计划条目数 / 全部计划条目数`。
- 同时报 `PCR_ex_one_shot`：剔除 `join_sect/open_shop/found_sect` 等一次动作即完成的目标，防止用易目标刷分。
- 基线：R 臂全目标完成 **24/117 = 20.51%**；M 臂 **29/115 = 25.22%**（V4；这是“规则隐式计划”的暂用基线，阶段 0 用同一审计脚本计算精确的 3 日隐式计划基线后锁定）。
- 目标：**≥32%**（严格）；**≥28%**（最低可接受）。`PCR_ex_one_shot` 不得低于 R 基线。

### M2 计划中断率 PIR（Plan Interruption Rate）

- 计算：`PIR = 在完成或到期前被替换/放弃/迁出计划的条目数 / 全部计划条目数`；紧急暂停 <1 天不计中断。
- 基线：R 丢弃率 **67.52%**（79/117），切换 105；M 丢弃率 **64.35%**（74/115），切换 105。
- 目标：**≤45%**（严格）；**≤55%**（最低可接受）。

### M3 长周期目标达成 LHGA（Long-Horizon Goal Attainment）

- 计算：每个 NPC 每 10 游戏日完成的、创建与完成都在窗口内的目标数；同时单独报“创建时计划寿命 ≥3 天”的目标完成数。
- 基线：R **24/31 = 0.774 个/NPC/10 天**；M **29/31 = 0.935**。
- 目标：**≥1.10 个/NPC/10 天**（严格，约 +42% vs R）；**≥1.00**（最低）。

### M4 跨日行为一致性 CDC（Cross-Day Consistency）

- 计算：对每个 NPC，取每天成功非 system 动作的 verb 分布，计算相邻两个游戏日分布的余弦相似度；对所有 NPC-日对求均值。
- 基线：R **0.8764**、M **0.8274**（V6）。
- 目标：**≥0.90**（严格，≥+2.4pp vs R）；**≥0.88**（最低）。

### M5 单位成本收益 CEG（Cost per Extra Goal）

- 计算：`CEG = 本臂 LLM 总成本 / max(1, 本臂完成目标数 − R 臂完成目标数)`；同时报 `K1 每多推进 1 个目标的成本`。
- 基线：当前 M 臂 **$3.0 / (29−24) = $0.60 / 个新增完成目标**；K1 新增为 0，成本收益无穷差。
- 目标：**≤$0.20 / 个新增完成目标**（严格）；**≤$0.30**（最低）。按 $1.5/10 天算，严格线要求至少 **+7.5 个**完成目标（≥32 个）。

### 护栏指标（不作主判据）

- **K1 护栏**：战略臂 K1 **不得低于 R − 2pp**（即 ≥54.04%）；不以 K1 提升作为成功条件。
- **计划执行缺口 PEG**：到期前从未被规则 planner 安排过任何动作的计划条目 / 全部条目；**≤20%**，否则说明计划不可消费。
- **K6/回放**：守恒、已执行非法、含剪枝非法 <2%、`event_hash` replay MATCH；任一失败即整轮无效。

## 5. 成本模型与“什么条件下才值得”（问题 4）

### 5.1 单价假设

按 `config/llm.yaml`：输入 **$0.0015/1k**、输出 **$0.0060/1k**；LOD 档位倍率按初始分布加权：
`0.20×0.25 + 0.40×0.5 + 0.30×1.0 + 0.10×2.0 = 0.75`。

单次战略调用按 **6k 输入 + 500 输出**：
`(6×0.0015 + 0.5×0.006) × 0.75 ≈ $0.009/次`。

### 5.2 总成本估算

| 方案 | 调用/10 天 | 10 天估算 | 调用/72 天 | 72 天估算 |
|---|---:|---:|---:|---:|
| S0：1 次/NPC/3 天，6k/500 | 124 | **≈$1.12** | 744 | **≈$6.70** |
| S0：同样频率，8k/700 | 124 | **≈$1.51** | 744 | **≈$9.04** |
| S1：1 次/NPC/天，6k/500 | 310 | **≈$2.79** | 2,232 | **≈$20.1** |
| 当前 decision 选择器（对照） | 438 | **≈$3.0** | 2,201 | **≈$9.5** |

**关键结论**：战略层必须**替代**当前 decision 选择器。若叠加，10 天约 **$4.1–4.5**，高于当前 $3.0，直接不值得。

### 5.3 值得做的门槛（全部满足才继续）

1. **成本**：10 天总 LLM 成本 **≤$1.5**；72 天 **≤$9.0**；调用数 10 天 **≤130**、72 天 **≤780**。
2. **效果**：`PCR ≥30%` 且 `PIR ≤45%` 且 `LHGA ≥1.0` 且 `CDC ≥0.90`；`PCR_ex_one_shot` 不低于 R 基线。
3. **效率**：`CEG ≤$0.20/个新增完成目标`，且 10 天新增完成目标 **≥5 个**。
4. **不伤世界**：K1 ≥R−2pp；K6 严格与含剪枝 pass；replay MATCH；run 期间 `content_hash` 不变。
5. **可复制**：先 1 个 seed 通过；若要默认开启，必须再做 1 次 72 天确认（另行预算 ≥$9，不在本轮）。

任一条不满足 → **不值得**，不进入默认路径。

## 6. 分阶段验证与预算/停止规则（问题 5）

### 阶段 0：离线 fake 端点（$0）

- 内容：fake/replay transport 返回固定 `StrategyPlan` 夹具；跑 3 天/8 NPC 与 10 天/31 NPC；只验证 schema、消费、承诺、护栏、回放。
- 预算：**$0**，禁止真实网络。
- 通过条件：计划合法率 100%；规则动词/动作参数泄漏 0；紧急目标被覆盖 0；周期内换计划 0；关闭开关时 golden 不变；开启开关时 replay MATCH。
- 停止规则：任一 schema 失败、计划执行缺口 >20%、或回放不一致 → 先修设计/夹具，不进阶段 1；修 2 轮仍失败则判“不可消费”，路线失败。

### 阶段 1：小规模真实 run（3 天 / 8 NPC，1 个战略周期）

- 调用：8 次（day 0 一轮），估算 **$0.08–0.12**；硬上限 **$0.25**。
- 通过条件：schema 合法 ≥95%；至少 2 个计划条目完成；PIR ≤60%；K6 pass；单次成本 ≤$0.02。
- 停止规则：0 个计划条目完成、PIR >70%、schema <90%、或成本 >$0.25 → 停，不跑阶段 2。

### 阶段 2：一次对照（10 天 / 31 NPC / seed 42）

- 设计：S 臂 = 战略层 + 规则 planner；R 臂直接复用冻结快照 `runs/a3-rule-10d-31npc-frozen`，不重复烧钱；同 `content_hash=fac4ac31…`。
- 调用：124 次；估算 $1.12–1.51；预算 **soft $1.5 / hard $2.0**。
- 中期停止：day 5 结束时若累计成本 >$1.5、或计划完成率低于 R 基线 20.51%、或 K1 <R−3pp，立即停。
- 通过条件：第 5.3 节门槛全部满足。
- 停止规则：触发 soft/hard、K6 失败、replay 不一致、或 `content_hash` 变化 → 整轮判无效，不降阈值、不重试；预算未用尽且失败原因是实现 bug 时才允许一次修复后重跑。

**本轮真实调用总预算上限：$0.25 + $2.0 = $2.25**；累计到 $2.5 必须停。72 天确认不在本轮预算内。

## 7. 风险与“出现什么就说明失败”（问题 6）

| 风险/失败结论 | 触发条件 | 说明 |
|---|---|---|
| R1 战略选择比规则差 | PCR <20.51%（R 全目标完成基线）或严格线 <30% | 说明模型的多日组合没有价值 |
| R2 承诺无效 | PIR ≥67.52%（未低于 R）或 >55% | 计划仍被频繁打断，战略层没有约束力 |
| R3 一致性没改善 | CDC <0.8764（低于 R）或严格线 <0.90 | 计划没有带来跨日连续性 |
| R4 组合伤害世界 | K1 <R−3pp，或核心类型配额被系统性破坏 | 重演 A3 的“类型替换”失败 |
| R5 靠易目标刷分 | PCR 提升但 `PCR_ex_one_shot` 低于 R 基线 | 只是挑了 `join_sect/open_shop` 等一次性目标 |
| R6 计划不可消费 | PEG >30%（到期前从未被 planner 安排动作） | 战略产出物与规则层接口失败 |
| R7 经济性不成立 | 10 天 >$1.5，或 CEG >$0.30/新增完成 | 即使指标改善，也不值得上线 |
| R8 世界被破坏 | K6 含剪枝 ≥2%、守恒误差 ≠0、replay 不一致 | 整轮无效，不得用其他指标宣称成功 |

## 9. 如果失败，替代方向

1. **内容扩充优先（首选）**：V3 已证明 49.45%→56.04% 来自内容；继续加目标/关系/事件比再烧模型更便宜。
2. **LLM 只做对话/叙事层**：玩家可见文本、氛围、传闻；但盲评 55.9% 无显著优势，先改模板与文本护栏，且不以 K1 宣称成功。
3. **离线内容生成器**：LLM 批量生成目标/任务/传闻，规则引擎校验后冻结进内容包；运行时零模型成本。
4. **Spotlight 咨询层**：只对 10% 高活跃 NPC、只给建议、规则保留否决权；预算 ≤$0.3/10 天，衡量 K3 多样性而非 K1。
